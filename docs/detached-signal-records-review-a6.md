# Adversarial review: detached-signal-records.md, revision 6

Verified against `/Users/jitl/src/alien-signals-opt/packages/dalien-signals/src/index.ts` and `src/system.ts` in the working tree, with all five hardenings assumed landed exactly as v6 specifies them. Verdict up front: v6 genuinely closes the v5 fatal — the queue-time generation bump plus queue-time cache-clear kills every free-to-sweep construction from a5-1/b5-1, and I could not rebuild that window. But the headline relocation was specified without auditing the host code it lands inside: the freed hook (`freedNode`, index.ts:735-758) is the host's *column-release* seam, and dispatching it at logical-free time clears exactly the columns `disposeEffect` reads immediately after `freeNode` returns. As written, every effect cleanup is silently skipped and every scope disposal leaks its region. One FATAL, four MAJOR, three MINOR.

## Findings

**1. FATAL — Queue-time freed-hook dispatch clears `cleanups[]` and `owned[]` before `disposeEffect` reads them: cleanups stop running and scope regions leak, on the main dispose path.**

Hardening 1: "The queue-time free … now bumps the generation and dispatches the freed hook immediately," and the v5-answer section confirms "the freed-hook dispatch move[s] to logical-free time; the sweep only zeroes slots and stacks the record." The freed hook is the existing `freed` seam — host `freedNode` — whose job is releasing all five host columns, including `cleanups[idx]` and `owned[idx]` (index.ts:743-757). But `disposeEffect` reads both AFTER calling `freeNode`:

1. `dispose(effectWithCleanup)` → `disposeEffect` (index.ts:587): `fns[idx] = undefined` (592), `freeNode(id, gen)` (593).
2. Under v6, `freeNodeId` dispatches the freed hook before returning → `freedNode(id)` clears `cleanups[idx]` and `owned[idx]`.
3. `disposeEffect` resumes: `if (cleanups[idx])` (594) → undefined → **the user's cleanup never runs**.
4. For a scope: `const region = owned[idx]` (597) → undefined → the region is never queued to `freePendingRegions` → every raw `signalId`/`computedId` created inside the scope is **never freed** (raw ids have no registry) — a permanent leak until `reset()`.

Same break via every route into `disposeEffect`: the `unwatched` cascade for child effects (index.ts:771-773), and the reset walk (system.ts:935-944 → host `unwatchedNode` → `disposeEffect`), so reset stops running cleanups too. This is precisely the invariant a5-7 flagged as load-bearing ("no code reads a queued id's host columns across a bracketed user-code exit") — v6's resolution map claims that invariant is "stated," it appears nowhere in the body, and v6's own mechanism now violates it unconditionally (no sweep needed — the hook fires inside the free). The repair is small (stash cleanup/region into locals before `freeNode`, or split the hook so column release stays at the sweep and only the cache-clears run at queue time), but the spec specifies neither, and its "the sweep keeps its slot-zeroing" enumeration forecloses the second reading. Defeats: correct disposal, region ownership, the NEVER-LEAK rule, obligation 24's own subject matter.

**2. MAJOR — With the freed hook no longer dispatched at the sweep, host-column stores that land after the queue-time free are never cleared: a self-stopping effect's returned cleanup is pinned forever.**

Today the sweep-time `freeNode` runs `hostFreed` (system.ts:1243-1246), which catches columns repopulated between logical free and sweep. Under v6 the sweep "does not bump again" and "only zeroes slots and stacks the record" — no second hook dispatch. Scenario: `const stop = effect(() => { stop(); return () => release(); })`. `dispose` runs mid-body (queue-time hook clears columns), then `effectId`'s try block executes `cleanups[idx] = fn()` (index.ts:513; same store in `run` at 844) — repopulating the freed record's cleanup slot AFTER the only hook dispatch. Nothing ever clears it: the closure (and everything it captures) is pinned until the record is recycled by another *effect*; recycled as a signal it is pinned indefinitely, and the cleanup itself never runs. A new leak class introduced by the relocation. (Note findings 1 and 2 cannot both be fixed by choosing a dispatch time: queue-only breaks `disposeEffect`, sweep-only is v5's fatal, both-times still breaks `disposeEffect`. The host-side reads/stores must be reordered or generation-guarded, and the spec says nothing about either.)

**3. MAJOR — Hardening 5's exit-sweep runs at EnterDepth-zero instants that are not walk-quiescent: node records freed by a getter's `dispose()` are recycled mid-`checkDirty`, and the unwind then drives update/Pending decisions off a recycled stranger.**

EnterDepth brackets *user code* frames only. `checkDirty` runs unbracketed at depth 0: `run()` evaluates it before its bracket (index.ts:823 vs 840), and top-level `getSlow` does too (967). An `updateComputed` inside that walk brackets 0→1→0 (798, 810), so its exit is a "frame exit at depth zero" — a sweep site per hardening 5's letter. Scenario, all public raw-tier API:

1. `S = signalId(0)`; `Y = computedId(() => { if (kill) dispose(X); maybeCreateNodes(); return get(S); })`; `X = computedId(() => get(Y))`; `E = effectId(() => { get(X); })`.
2. Top-level `set(S, 1)` → flush → `run(E)` → `checkDirty(E.deps, E)` at EnterDepth 0; the walk descends E→X→Y, pushing the E–X and X–Y links onto `checkStack`.
3. `updateAndShallow(Y)` runs Y's getter with `kill` set: `dispose(X)` → `freeNodeId(X)` unlinks E–X (**held on `checkStack`**) and queues X.
4. Y's getter returns; `updateComputed(Y)` exits; EnterDepth hits 0 → **hardening-5 sweep** → X's node record goes to the free stack; X's freed link records are already reusable (links recycle immediately, system.ts:1318-1326).
5. Still inside the same walk, `maybeCreateNodes()` in a later getter (or Y's own, before returning) allocates: X's node record is recycled to live stranger Z; the freed E–X link record can be rewritten as a foreign edge by a `link()` call.
6. The unwind pops the stale/recycled links: `updateAndShallow(sub, …)` fires `update()` on Z (spurious recompute, early commit of Z's staged write, spurious `shallowPropagate` of Z's subs), or `M[sub + Flags] &= ~Pending` clears a real Pending on the stranger; through a rewritten link the walk wanders into a foreign dep chain and resolves E's dirtiness off it — E re-runs spuriously or goes permanently stale.

Under today's microtask-only sweep, step 5 is impossible and the host's freed-mid-walk guard (index.ts:785-788, `fns` cleared → "treat as changed") absorbs step 6. Hardening 5's safety argument — "every queue that could name swept records is generation-guarded" — does not cover the kernel traversal stacks (`checkStack`/`propStack` hold link ids whose Dep/Sub fields name node records) or `chainCheck`'s stackless climb. The doc also contradicts itself: detach step 3 justifies its own safety by "the operation-boundary sweep, which is the same mid-walk safety envelope the kernel already grants orphaned records" — the envelope hardening 5's letter punctures. The safe placement (outermost public-entry returns, where no walk can be live) satisfies the churn-loop motivation but is neither stated nor distinguished. Adjacent pre-existing bug, unfiled by the doc's five: held freed *link* records can be reused mid-walk today by user link creation inside a getter that disposed a node the walk descended through — that should be bug #6.

**4. MAJOR — The retained frameless growth sites are under-enumerated: `effectId` and `effectScopeId` allocate before their enter-depth bracket and continue in the retired generation across a mid-call growth. Bug #4 has at least four sites, not two; "the entry trampolines are host-stack-empty at that instant" is false for these entries.**

`effectId`: alloc at index.ts:496, bracket at 510; `effectScopeId`: alloc at 537, bracket at 552 — the exact shape the doc files for `trigger` (645 vs 662). Scenario, today-reachable: a top-level creation burst crosses 3/4 capacity (growPending set, system.ts:1234-1237); the next top-level `effect(fn)` → `facade.allocNode` → `maybeBoundary` (EnterDepth 0) → `grow()` retires the host generation mid-`effectId`. The rest of `effectId` executes in the old closure over the retired, zeroed arena (retire() at system.ts:1081-1092): `activeSub = id` lands in the dead generation's let while module trampolines route `fn()`'s reads to the new host whose booted `activeSub` is the pre-call value — **the effect body runs untracked and the effect is born inert**; `++M[SysSlot.EnterDepth]` (510) brackets the dead arena, so the live arena reads depth 0 during `fn()` and a second growth can retire an arena under a live user frame — the exact class hardening 5 exists to prevent; the finally's `&= ~RecursedCheck` (518) writes dead memory, so the live record keeps RecursedCheck forever. Under a manual frame (`setActiveSub` at top level), `link(id, prevSub, 0)` (507) inserts the parent-child edge into the dead arena — the child is never disposed by its parent: a leak. The kernel-side forwarding of `createNode`/`allocNode` itself is sound (newCustom's retired check, system.ts:1179-1187; shared columns; gens copied verbatim) — the unsoundness is entirely the callers' continuation, and `computedId`'s scoped gen read (index.ts:479) shares site 1's class alongside `signalId`'s (434). The fix family is the one already specced for trigger (bracket before allocating); the spec must name these sites.

**5. MAJOR — Consume-the-head covers the three named walks but not the class: `purgeDeps` and `trigger`'s teardown loop keep cached next pointers under unlink cascades that run user code, and the rule's letter cannot be implemented for the filtered child-effect walk.**

`unlink` delivers `unwatched` synchronously (system.ts:1406-1410) → a cold computed's dep-drop → child-effect disposal → `runCleanup` → user code. That can run under `purgeDeps` (index.ts:936-942, resumes at `l = unlink(...)`'s cached return) and under `trigger`'s finally loop (index.ts:669-679, `l = unlink(l, id)`): the cleanup disposes the purging sub (or another holder of the cached-next link), the link record recycles via a fresh `link()` in the same cleanup, and the walk resumes on a foreign live edge — `unlink(foreign, sub)` then rewires the foreign chain against the wrong sub (system.ts:1390-1399). Hardening 1 does not intercept this: the cleanup's dispose is a legitimate first free, and the walks re-check no generation. Separately, hardening 2's normative rule — "unlink whatever the head slot currently names, until it names nothing" — is unimplementable verbatim for `disposeChildEffects` (index.ts:916-925), which must *skip* non-effect deps: a signal at the head is never consumed, so the loop as stated either spins or needs a cursor discipline the spec doesn't give (e.g., re-scan from the head, unlink the first effect found, repeat).

**6. MINOR — The registry pair's generation-capture point is unpinned.** a5-3 explicitly flagged the `pendingRegister` (owner, bare id) leg; v6 says only "the registration's held value becomes an (id, generation) pair." Captured at the microtask drain (the natural minimal diff — `registry.register` happens there, system.ts:812-820), a record disposed and recycled between create and drain registers the *stranger's* current generation and validates against it — reintroducing bug #5 one hop later. The pair must be captured at `createNode`/`adoptNode` time; obligation 25 as worded does not distinguish the two.

## Per-surface disposition (the brief's four)

1. **Queue-time generation bump**: not refuted. Nothing needs the generation stable across the window — the effect queue (index.ts:889, 874), region entries (624), `dispose`'s Live check (569), `freeNodeId`'s own guard, and the v6 registry pairs all want the mismatch from the moment of the free; the sweep's no-rebump is consistent; growth migration copies bumped gens verbatim (system.ts:1014-1019); double-push into `pendingFree` remains Live-gated. Residue: finding 7(b) and 7(e).
2. **Queue-time freed-hook dispatch**: **refuted** — findings 1 and 2. The hook body itself (column clears + cache compares) runs no user code and is re-entrancy-safe; the collision is with the host's post-free column reads and stores, which the spec never audited.
3. **Frameless growth / in-flight createNode forwarding**: forwarding of the allocation itself verified sound; the surrounding claim is not — finding 4. The v5 assertion generalized from `signalId`-unscoped (which is genuinely safe) to all creation entries; `effectId`/`effectScopeId` disprove the generalization.
4. **End-to-end detach mechanics**: not refuted. Re-verified under v6: `pendingVals` copy-out is lossless in batch/manual mode; the hook-presence gate makes double dispatch and the reset-sweep masquerade no-ops; attach rollback is clean and bracketed (growth cannot move the arena mid-attach); a re-read pre-sweep attaches fresh; transient last-unlink→relink in one flush detaches then re-attaches with the value preserved; the reset contract holds and `resetState` drops `pendingFree` wholesale (no double free); the self-stop-and-spawn scenario now yields a root child with no ghost edge. The failures above all enter through the hardenings' interactions, not the detach mechanism.
