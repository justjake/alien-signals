# Adversarial review: detached-signal-records.md, revision 3

Verdict: v3 is refuted. Hardening 1's central claim — "a dead subscriber has no surviving links to re-mark" — is false in the code (the dispose walk starts at `DepsTail`, which a running frame has reset), and its live-flag gate is identity-blind under record recycling, so both v2 FATAL ghost constructions survive the fix that claims to close them. Hardening 3 blesses a mid-update state that corrupts the link free list before the re-drop ever runs. Three FATAL, four MAJOR, three MINOR.

## Findings

**1. FATAL — Hardening 1 is defeated by the re-mark fast path: a subscriber disposed during its own run keeps a live edge, through public API, with the insert gate never consulted.**
The claim "with inserts gated, a dead subscriber has no surviving links to re-mark (its edges were unlinked at disposal)" is false: `freeNodeId`'s dep teardown is `disposeAllDepsInReverse`, which walks backward from `M[id + DepsTail]` (system.ts:1209, 1804-1811) — and a running effect reset `DepsTail` to 0 at run entry (index.ts:836). Scenario:
1. `const s = signal(0)` (detachable under v3); `let armed = false; const stop = effect(() => { if (armed) stop(); s(); })` — first run links L1: s→E.
2. `armed = true; s(1)` → `run(E)`: `DepsTail = 0`, body calls `stop()` → `disposeEffect` → `freeNodeId(E)`: flags zeroed, dep walk starts at `DepsTail = 0` → **unlinks nothing**; L1 survives with a dead Sub (system.ts:1193-1218).
3. Body continues: `s()` → `link(s, E)`: `prevDep = 0`, `nextDep = M[E + Deps] = L1`, `M[L1 + Dep] === s` → **re-mark fast path** (system.ts:1336-1339): version stamped, `DepsTail = L1`. No insert, no gate.
4. Run exit: `purgeDeps(E)` drops only links *after* `DepsTail` (index.ts:936-942) — L1 survives.
5. The sweep's `freeNode` zeroes E's slots **without unlinking** (system.ts:1243-1253); L1 stays in s's subscriber list forever. s never detaches (hook + closure pinned permanently — a leak, disqualifying by the design's own rule), and once E's record is recycled, `propagate` walks L1 into the new occupant: `notify` passes the occupant's **current** gen (system.ts:1752), so the queue's gen guard passes and an unrelated effect re-runs on every `s` write.
The same construction works for a computed disposed inside its own getter (`dispose(cid)` routes to `freeNodeId`, index.ts:572-577), with a bonus: `freeNodeId` dispatches `hostUnwatchedNode` first, whose Computed branch runs its own `disposeAllDepsInReverse` (index.ts:763-770), then `freeNodeId` runs a second reverse walk from the now-dangling freed `DepsTail` — the double-unlink free-list corruption index.ts's own comment warns about (index.ts:582-586) is guarded for effects (`fns` cleared first) but **not for computeds**. Defeats §Prerequisite hardening 1, §The hook is the pin, obligations 12-13, and the resolution-map claims for a2-1 and a2-2.

**2. FATAL — The liveness gate passes on a recycled occupant: the v2 manual-frame scenario plus a pending-free backlog re-creates the ghost through the gate, in one synchronous frame.**
The gate reads `Flag.Live` of whatever currently occupies the record; `activeSub` is a bare id with no generation, so the gate cannot check identity. Scenario (all public API):
1. Create and dispose ~8,200 throwaway effects (`pendingFreeEnd > 8192`, `boundaryPending` set).
2. `const e = effectId(noop); const prev = setActiveSub(e); dispose(e);` — e queued last on `pendingFree`.
3. `const f = effectId(fn)` — `effectId`'s alloc runs `maybeBoundary` with `EnterDepth === 0` (manual frames never bump it) → `boundaryWork` sweeps (system.ts:1140-1150, 1147), e's record tops `nodeFreeStack`, and `allocNode` pops it: **f now occupies e's record**. `effectId` restores `activeSub = e` on exit (index.ts:517).
4. `s()` (detached signal) → attach → `link(s, e)`: the gate loads the occupant's flags — Live (it's f) — and **inserts**. f re-runs whenever s changes, though f never read s; tracking is attributed to the wrong subscriber.
"Dead subscribers simply never gain edges" is therefore false exactly in a2-1's frame shape, which this hardening exists to close. Defeats §Prerequisite hardening 1 and the a2-1 resolution claim.

**3. FATAL — Hardening 3's supported flow corrupts the arena before the update-exit re-drop can run: the mid-update unwatched drop leaves `DepsTail` dangling on a freed link, and the next first-read insert re-issues that link as its own `prevDep` — a self-referential dep list and an infinite unlink loop.**
The mid-update drop (`unwatchedNode`'s Computed branch, index.ts:763-770) unlinks from `DepsTail` backward; when a stale successor exists, `unlink` of the tail has `nextDep !== 0` and never repairs `M[sub + DepsTail]` (system.ts:1390-1393) — `DepsTail` now names a freed link on top of `linkFreeStack`. Scenario: effect E watches computed C (prior deps [Ltick, Lold]); `tick(1)` recomputes C; the getter reads `tick` (re-mark, `DepsTail = Ltick`), calls `stop(E)` (→ C unwatched mid-update → drop: Ltick freed, `DepsTail` dangles), then **first-reads a fresh detachable signal** — v3's core path: attach → `linkInsert(v2, C, ver, prevDep = Ltick, nextDep = Lold)` → `allocLink` **pops Ltick** as the new link (system.ts:1300-1304); since `newLink === prevDep`, the writes `M[newLink + NextDep] = nextDep` then `M[prevDep + NextDep] = newLink` (system.ts:1361, 1368) leave `M[Ltick + NextDep] = Ltick` — a self-loop. `purgeDeps` (and hardening 3's re-drop, which walks the same list) then unlinks Ltick, gets Ltick back as `nextDep`, and loops forever, pushing Ltick onto `linkFreeStack` unboundedly. The looseness is pre-existing, but v3 (a) makes first-read inserts the default signal's standard behavior and (b) explicitly declares "loses its last subscriber mid-run and then keeps reading" a supported state to be tidied at update exit — an exit that is never reached. Hardening 3 cannot be a cleanup pass over a list that can be cyclic. Defeats §Prerequisite hardening 3, obligation 14, and the b2-2 resolution claim.

**4. MAJOR — Attach has no rollback for link REFUSAL, only for link throw: every gated read of a detached signal leaks one arena record.**
Attach steps 1-2 allocate and seed the record; step 3's rollback triggers only "if link allocation throws." Hardening 1's gate refuses without throwing ("the read returns the value untracked"). After refusal: record allocated, no link, step 4 gated on "after the link exists" so no hook and no closure id — nothing owns the record (no registry, no links, no hook, no closure reference). A loop reading detached signals under a doomed manual frame leaks arena records unboundedly. Obligation 12's "nothing is pinned (GC-checked)" tests the JS heap, which never sees arena records. The spec must gate before allocating or specify refusal rollback; it does neither. Defeats §Mechanics step 3 and the hardening-1/attach integration.

**5. MAJOR — The enter-depth bracket starves growth and the sweep in workloads whose only allocations are attaches: a constant-live-set `trigger()` loop that runs forever today exhausts the arena and throws under v3.**
v3 removes record allocation from `signal()` creation — the former boundary site — and brackets attach's allocation, so `maybeBoundary` (the only synchronous growth/sweep gate, system.ts:1140-1150) never fires in loops where attaches are the only allocs. `for (;;) trigger(() => s())` over an otherwise-unwatched detachable: each iteration attaches (one node record, inside trigger's own `EnterDepth` bracket) and detaches (node record → `pendingFree`, recycled only at a sweep). Links recycle immediately via `freeLink`, but node records do not; microtasks never run in a synchronous loop; no facade alloc ever executes at `EnterDepth === 0`. Result: monotonic record consumption, `growPending` set at 3/4 and never applied, hard throw at capacity (~2M iterations), plus a multi-million-entry `pendingFree` array. Today the same loop allocates zero records steady-state. This is not the documented "mass first-reads inside one tracked frame" limitation — boundaries exist between iterations; the design's own machinery erases them. No gate or obligation covers it (the oscillation micro uses `effect()`, whose creation alloc provides boundaries). Defeats §Documented limitation and §Mechanics step 1.

**6. MAJOR — The bracket's exception safety is unspecified: a record-alloc throw at the hard capacity limit (step 1, inside the bracket, before any rollback target exists) can wedge the system permanently.**
`allocNode` throws on a full arena (system.ts:1230-1232). The doc's exception ordering covers only step 3's link throw; nothing states the enter-depth counter is finally-restored. Implemented as written, a step-1 throw leaves `EnterDepth` elevated forever: `busy()` is permanently true, maintenance no-ops, growth and sweeps never run, and `reset()` throws its active-operation guard (system.ts:1152-1156) — the one recovery path is dead. Obligations 4 and 16 force exhaustion only "at the link step," so the test suite as specified never exercises this. Defeats §Mechanics step 1 and obligation 4.

**7. MAJOR — The dedicated attach path drops load-bearing `signalId` internals: column growth and the full host-bits word.**
`signalId` calls `growColumns(idx)` before any column store (index.ts:427-430); attach step 2 stores into `currentVals[idx]`/`pendingVals[idx]` with no growth mention, and a bump-allocated record's idx always exceeds the columns' length. Consequences: holes → JSC sparse-ArrayStorage collapse (the codebase's own measured disaster, index.ts:283-290), and desynchronized column lengths breaking `growColumns`' one-length-check lockstep for every later creation. Step 1 likewise says only "the detachable host bit set": without `Host.Signal | Flag.Mutable` (index.ts:426), `updateNode` dispatches a Dirty detachable to `updateComputed`, finds no getter, returns "changed" and never commits `pendingVals` — reads go stale forever after the first batched write. The seeding internals were kept; these two were lost. Defeats §Mechanics steps 1-2.

**8. MINOR — The §reset() contract is false under v3's own mechanics: attached callables do not "still hold their pre-reset id."**
The reset walk dispatches `hostUnwatched` for every HostStarted node (system.ts:934-944); an attached detachable has a populated hook, so the Signal branch runs the full detach: value copied out, **closure id reset to 0**, hook cleared. After reset the callable is a working detached signal that re-attaches into the new arena — the exact survivor conversion b2-5 flagged, now contradicting v3's replacement text ("An attached callable's closure still holds its pre-reset id afterwards") instead of v2's. The contract is fine; the stated mechanics are wrong again. Defeats §`reset()` contract; b2-5 resolution claim.

**9. MINOR — Gate residue: the band-vs-ratio contradiction survives verbatim, memory gates still have no method or number, and the oscillation budget's measurement window excludes detach's deferred costs.**
(a) The protocol says thresholds are "expressed relative to that band, not as a bare ratio," then issues bare ratios (2.0x, 1.05x). (b) "Roughly a wash, must not regress" and "must drop decisively" still name no heap-measurement method or threshold — b2-4's core objection, claimed resolved. (c) Detach defers reclamation to boundary sweeps (pendingFree push + eventual sort, system.ts:1263-1292); the protocol never places maintenance inside the measured window, so the oscillation micro can pass 2.0x while the sweep/sort cost lands between samples — gameable by window placement. Defeats §Costs and gates; a2-8 and b2-4 resolution claims.

**10. MINOR — Hardening 2 covers `effect()` only; a throwing first `effectScope()` run leaks identically, and scope bodies track reads.**
`effectScopeId` sets `activeSub = id` (index.ts:546-547), so detachable signals attach against the scope during its body; its finally restores state without disposing on throw (index.ts:552-559), and no stop is returned. The mass-first-read exhaustion shape the limitation section analyzes therefore leaks the scope record, its region, and its child effects when the wide read lives in a scope body — outside hardening 2's coverage and obligation 18. Defeats §Prerequisite hardening 2's coverage claim.

## Surfaces not refuted (genuine effort)

- **Attach steps 3→4 gap**: not refuted — straight-line code, `watched` undefined in this host, `hostWatchedNode` runs no user code (system.ts:1418-1432).
- **Hook-presence gate vs the reset-sweep masquerade**: not refuted — node and link free stacks are segregated and fresh records get hole-free `undefined` column slots, so a link record's index never carries a stale hook; a masqueraded dispatch finds no hook and no-ops.
- **Double `unwatched` with a cleared hook**: not refuted — `HostStarted` cleared before dispatch (system.ts:1434-1436), re-arm needs a new first link to an abandoned id.
- **`pendingVals` always-newest at detach**: not refuted — `setHot` stores unconditionally (index.ts:1025), commits copy pending→current only (index.ts:778).
- **Kernel unwatched ordering as restated**: confirmed — version snapshot zeroed after the host dispatch (system.ts:1756-1766); detach step 3's parenthetical now matches the code.
- **Region exclusion via the dedicated path**: not refuted — no other attach-time region join exists (a2-3's construction is closed as specified; obligation 15 is the right test).
- **Migration-mid-attach prevention**: not refuted — the bracket does block all three growth entry points (`maybeBoundary`, `runMaintenance`'s busy check, `growCapacity`'s busy check); the a2-4 corruption is closed (at the cost of finding 5).
