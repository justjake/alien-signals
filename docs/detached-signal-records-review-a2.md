# Adversarial review: detached-signal-records.md, revision 2

Verdict: v2 is materially sounder than v1 — the pendingVals rule, the seam-based detach, and the attach rollback all check out against the real code. But the ghost-link prerequisite is insufficient for the premise it exists to establish (two public-API constructions survive it), and the attach mechanics as literally written reintroduce scope ownership at attach time with a double-free consequence. One FATAL, four MAJOR, four MINOR.

## Findings

**1. FATAL — The ghost-link hardening does not establish "a link proves a live subscriber": manual tracking frames construct ghosts after it lands.**
The hardening (§Prerequisite hardening) hooks "run exit" of an effect. Manual frames have no run exit, and `setActiveSub` (public, exported, the documented raw-tier framework seam, index.ts:1216) neither brackets `EnterDepth` nor checks subscriber liveness at link time. Scenario:
1. `const e = effectId(() => {})` — a live effect record.
2. `const s = signal(0)` — detachable, born detached.
3. `const prev = setActiveSub(e)` — manual tracking frame.
4. `dispose(e)` — `freeNodeId` unlinks e's edges, zeroes flags, queues the record (system.ts:1193-1218). `activeSub` is still `e`.
5. `s()` — tracked read (`activeSub !== 0`) → attach: record allocated, hook installed, `link(S, e)` inserts an edge whose subscriber is the dead record.
6. `setActiveSub(prev)`. No run exit ever fires; the boundary sweep's `freeNode` zeroes e's `Deps` slot **without unlinking** (system.ts:1243-1261), so the ghost edge stays in S's subscriber list forever.
Consequences: S's subs never empty → the hook pins the closure environment and the record permanently (a leak, which per the design's own framing is disqualifying); and when e's record is recycled off the free stack, S's `propagate` walks the ghost link into the new occupant — spurious Dirty/notify on an unrelated node. The leak-and-corruption class is pre-existing for registry signals, but v2 explicitly gates the whole design on this premise being made sound ("it must land and soak before detachment builds on 'a link proves a live subscriber'"), and after the specced hardening the premise is still false through public API. Defeats §Prerequisite hardening and §The hook is the pin.

**2. MAJOR — The hardening is effect-only; a computed disposed during its own recompute produces the same ghost.**
`dispose(cid)` is callable from inside the computed's own getter (raw tier: `computedId` returns the id the getter can capture). Scenario: effect E watches computed C; a write makes C recompute; C's getter calls `dispose(cid)` (dispose routes computeds to `freeNode` directly, index.ts:572-577 — flags zeroed, deps and subs unlinked), then the getter continues and reads detachable signal S → attach + ghost link S→dead-C. `updateComputed`'s finally purges only **after** `DepsTail` (index.ts:936-942), and `DepsTail` is the ghost link itself — nothing removes it. Same permanent pin as finding 1. The hardening spec says "an effect stopped during its own run … at run exit"; `updateComputed` has an exit that gets no check, and `effectId`'s first run (index.ts:512-519) has no purge at all, so the spec's "run exit" must be defined as *every tracking-frame exit* (effect first run, effect re-run, computed recompute, scope body) or the regression test passes while the class ships. Defeats §Prerequisite hardening.

**3. MAJOR — Attach as specced region-owns the record when the first tracked read happens inside a scope; the consequence is forced detach under live consumers plus a double pendingFree push (record aliasing).**
§Mechanics step 1 says attach uses "existing `signalId` internals minus registration." Those internals contain the region branch: `if (owner === undefined && currentScope !== 0) owned[scope].push(id, gen)` (index.ts:433-435). Attach passes no owner, and first tracked reads routinely happen inside scoped effects for signals created at module level — so the record joins the scope's region, directly contradicting the table note ("detachability changes nothing about scopes"). Then:
1. `const s = signal(0)` at top level.
2. `const stopScope = effectScope(() => { effect(() => s()); })` — attach happens here; record region-owned by the scope.
3. `const stopE = effect(() => s())` — a second, outside consumer.
4. `stopScope()` — the scope's effect unlinks (subs: still stopE, no detach), then the deferred region flush calls `freeNode(s, gen)`: gen still matches (bumps only at sweep, system.ts:1252), record Live, HostStarted → `hostUnwatchedNode` → the new Signal branch **detaches**: copies pendingVals, resets the closure id, reclaims — pendingFree push #1. Control returns to `freeNodeId`, which proceeds unconditionally: unlinks stopE's link (stopE silently loses its dependency — future `s(v)` writes go to the closure with no propagate, stopE never re-runs) and pushes the id again — pendingFree push #2 (system.ts:1205-1216). The sweep runs `freeNode` twice; `nodeFreeStack` holds the id twice; two later allocations alias one record. The §Double-free defense does not cover this: the live-flag check ran *before* the dispatch that freed the record, and the cleared hook only defuses a second *unwatched*, not the remainder of the same `freeNodeId` call. Obligation 9's wording ("scoped default callables") reads as creation-in-scope and would not necessarily exercise attach-in-scope. Defeats §Mechanics (attach step 1), the taxonomy table note, and §Double-free defense.

**4. MAJOR — "Attach runs inside a tracked frame where growth is deferred" is false for manual frames; growth mid-attach writes links into the retired arena.**
Attach's allocation goes through `deps.sys.allocNode` → `maybeBoundary()`, which performs the arena migration whenever `EnterDepth === 0` and growth is pending (system.ts:1140-1150). `activeSub !== 0` (the attach trigger) does not imply `EnterDepth !== 0`: `setActiveSub` frames leave it at 0. Scenario: synchronously create enough nodes to cross `growAt` (growPending set, maintenance microtask not yet run), then `setActiveSub(effectId(...))`, then read a detached callable. Attach's alloc migrates the arena and forwards, returning an id in the **new** arena; attach then executes step 3's `link` through the *current host generation's closure-captured* `M`/`link` — which for the generation that entered the read is now the retired, zeroed arena. Result: the edge lands in dead memory, the real record never gains a subscriber, `unwatched` can never fire, the hook pins the closure forever, and tracking is silently lost. (`effectId`'s alloc-then-`link(id, prevSub, 0)` has the same latent hazard today, but attach turns it from "creating a child effect inside a manual frame" into "the first read of every detached signal inside a manual frame.") §Documented limitation promises a *clean throw* as the worst case of mid-frame allocation; this path is corruption, not a throw. Defeats §Documented limitation and §Mechanics step 3.

**5. MAJOR (pre-existing kernel bug the design builds on; v1 missed it) — The reset sweep cannot distinguish node records from link records, and §reset()'s delivery mechanism inherits that.**
`facade.reset` walks every record and dispatches on `M[id + NodeSlot.Flags] & Flag.HostStarted` (system.ts:935-944). For a **link** record, slot 0 is `LinkSlot.Version` — the host's cycle counter at link time. Once `cycle ≥ 8192`, half of all live links carry bit 13 (= `HostStarted`) and get `hostUnwatched` delivered; once `cycle ≥ 131072`, the Version's bits 16-18 masquerade as kind tags and the host's Computed branch performs `disposeAllDepsInReverse` on a link record, doing unlink surgery through node slots reinterpreted as link slots mid-reset. Today the damage is largely erased by the immediate `resetState` wipe. Under v2, a masqueraded Signal-detachable dispatch would mutate **closure state** (overwrite a value, reset an id), which reset does not wipe — the only thing standing between it and corruption is the hook-presence check, which §Mechanics does not make the branch gate (detach step 1 unconditionally "copy pendingVals[idx] into the closure via the hook"; the presence check appears only in §Double-free defense). Two obligations: the spec must make hook-presence the dispatch gate of the Signal branch, and obligation 10's reset test is blind below 8192 cycles as designed. Defeats §`reset()` contract and §Mechanics detach step 1 as written.

**6. MINOR — Two factual claims about the kernel are false.**
(a) Detach step 3 claims "the kernel's `unwatched` has already killed the version snapshot before the host dispatch runs." The code runs `hostUnwatchedNode` **first** and zeroes the snapshot after (system.ts:1756-1766). No live bug found (the reclaimed record's snapshot is unreachable and re-zeroed at sweep), but the step's correctness argument cites an ordering that does not exist. (b) §No refcount claims "the only kernel-side change is including detachable signals in the `unwatched` host dispatch" — no change is needed at all: the kernel's dispatch is already kind-agnostic (any `HostStarted` node, system.ts:1757), and `hostWatchedNode` already arms every first-linked node when `lifecycleArmed` (system.ts:1376-1380). The change surface is host-only; the spec should say so, because "kernel change" carries string-compiled-clone consequences it doesn't actually incur. Defeats the letter of §Mechanics/Detach and §No refcount.

**7. MINOR — `trigger()` over detachable signals is an ungated attach/detach cycle per call.**
`trigger`'s scratch subscriber makes every read inside `fn` tracked (index.ts:635-690); a detachable signal with no other subscriber pays record alloc + column seed + hook closure + link on entry and full detach + pendingFree traffic in the finally — per `trigger` call, in the API whose purpose is cheap in-place-mutation notification. Correct (the post-unlink `M[dep + Subs]` is 0, so no propagate is attempted for the sole-scratch case) but pure waste, and it belongs to the oscillation cost family while living in neither the oscillation micro nor the dynamic-dependency rows. Defeats §Costs and gates coverage.

**8. MINOR — Gate specification residue.**
(a) The protocol says thresholds are "expressed relative to that band, not as a bare ratio," then the acceptance criterion is the bare ratio "geomean must be ≤ 1.00" — self-contradictory and, within a noise band, ill-defined. (b) The oscillation "explicit budget" has no number, so "regresses more than creation-plus-memory gains justify" is not falsifiable as written. (c) The read/write gate ("read-heavy and update-heavy suite rows within the noise band") bounds the `id === 0` compare only if those rows exercise the **callable** tier; if the suite rows are raw-tier (`get`/`set`), the gate never executes the cost it claims to bound — the exact error class as v1 finding 8. (d) No gate covers teardown-heavy rows: disposing one effect over a wide detachable dep set now cascades N detaches (hook clear + reclaim + pendingFree each) inside the dispose path, which is neither a tracking pass nor propagation. Defeats §Costs and gates.

**9. MINOR — Taxonomy table error: `computed()`/`computedId` registers at create, not at first evaluation.**
`computedId` with an owner calls `createNode` immediately (index.ts:470-472); the "registers at first evaluation" claim is stale system.ts header lore (system.ts:80). Doesn't change any conclusion (computeds keep the registry either way), but the table presents itself as the normative reclaimer inventory and should be correct. Defeats the §Problem table's accuracy.

Additionally, on the hardening's behavioral edge (the brief's question "does it break legitimate dispose-during-run patterns"): yes, one — an effect that stops itself mid-run and then spawns a replacement child effect links that child to the doomed record (`effectId` links unconditionally when `prevSub !== 0`, index.ts:504-508); "unlink everything the doomed run tracked" kills the replacement at run exit, where today it survives (leaked-but-alive). The spec neither acknowledges nor tests this semantic choice; obligation 8 should pin it.

## Attack surfaces I could not refute (genuine effort)

- **Transient-empty subscriber lists during re-track**: not refuted. This codebase never unlinks a stale dep before run exit — `DepsTail` resets, old links persist through the body, `purgeDeps` runs only in the finally; out-of-order re-reads create duplicate links before the stale one dies, so a re-read dep's subs list never empties mid-run. `disposeChildEffects` unlinks effects only. The prompt's alien-v3 re-track fear does not materialize here.
- **Window between hook-run and sweep**: not refuted. Detach zeroes flags; every walk treats a zero-flags dep as clean (checkDirtyLoop's guards, propagate's mark ladder), freed links keep real neighbor fields by documented contract, and `allocNode` cannot re-issue a pendingFree-queued record (it is not on the free stack until sweep). This is exactly the orphan envelope.
- **Attach steps 3→4 gap**: not refuted for this host. Straight-line code, no user code between link insert and hook install: `hostWatchedNode` runs no callback (this host defines no `watched`), and `allocLink`'s throw precedes any list mutation and precedes arming. (Caveat only if a future host installs a `watched` callback — then user code runs mid-`linkInsert` before the hook exists.)
- **pendingVals always-newest**: not refuted. `setHot` stores into `pendingVals` unconditionally (equality-rejected writes included, index.ts:1025), `updateSignal` copies pending→current and never the reverse (index.ts:775-779), `freedNode` wipes only post-reclaim at sweep, column growth touches only virgin indexes, attach seeds both. Obligation 3's scenario works as claimed.
- **Double unwatched with a live hook**: not refuted, provided finding 5's hook-presence gate is made normative. `HostStarted` gates dispatch and is cleared before the host branch; re-arming requires a new first link to the abandoned id, which nothing can produce.
- **Leak taxonomy cross-paths** (registry-reclaimed computed reading a detachable signal, never-watched lazily-evaluated computed dropped while depending on one, scoped effects, cleanup-context reads with `activeSub = 0`): all traced to detach delivery through the existing `orphan`/`reclaimOrphan`/`unwatched` cascade; no unreclaimed configuration found beyond the ghost-link constructions in findings 1-3.

## The 11 v1 resolution-map items

1. Staged-write loss → **RESOLVED** — pendingVals verified always-newest on every write path; obligation 3 pins the batch/manual case.
2. Eager-attach paths unreclaimed → **RESOLVED** — the taxonomy matches the code's actual reclaimers (one cell error, finding 9, conclusion unaffected).
3. Scopes premise → **RESOLVED as stated** — creation-time non-membership is code-true (index.ts:433); but v2 reopens the same hazard at attach time (finding 3).
4. Growth-forbidden mass attach → **RESOLVED** for kernel-bracketed frames (honest limitation, rollback verified); the adjacent manual-frame growth hole is new (finding 4), not the v1 finding.
5. Redundant refcount / broken handoff → **RESOLVED** — refcount deleted; the watched/unwatched seams verified to arm and deliver exactly as the design assumes; plain hook column rides deps by reference like the other five.
6. Gate mis-specification → **PARTIALLY RESOLVED** — protocol, attach-inclusive creation, and the oscillation micro fix the v1 errors; the bare-ratio contradiction, unnumbered budget, callable-tier ambiguity, and missing teardown row remain (finding 8).
7. Spurious first-write wave → **RESOLVED** — both-column seed verified against `updateSignal`'s compare-and-commit.
8. Fictitious generation defense → **RESOLVED** — cleared-hook + live-flag are the real guards in this code (gen bumps confirmed sweep-deferred); caveat: the live-flag discipline does not cover the intra-`freeNodeId` double push of finding 3.
9. `reset()` parity overclaim → **RESOLVED** — the documented-UB contract matches the mechanism (delivery order, column-wipe order, boundary/pending clears all verified), modulo the pre-existing sweep misdispatch (finding 5).
10. Attach exception window → **RESOLVED** — hook installs strictly after the link; `allocLink` throws before any mutation; rollback leaves a working detached signal ("nothing pinned" is overstated by one sweep interval — seeded column slots persist until `freedNode` — but bounded and GC-equivalent).
11. Ghost links → **NOT RESOLVED** — the hardening covers effect-run exits only; ghosts remain constructible after it lands through `setActiveSub` manual frames (finding 1) and computed self-dispose mid-recompute (finding 2), both public API, so the premise the design builds on is still false.
